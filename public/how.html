How ERAS Works

A complete guide to the optimization model, algorithms, and API.

🧠 The Problem

In disaster relief operations, resources — rescue teams, medical units, supply convoys — are strictly finite. Multiple crisis zones compete for the same pool simultaneously. A coordinator must decide which zones receive resources to maximize total humanitarian impact within the available budget.

ERAS models this as a classic 0/1 Knapsack problem: each region is either fully funded or receives nothing. No partial allocations. The goal is to select the subset of regions that maximizes aggregate impact without exceeding resource capacity.

📐 Impact Formula

Each region is assigned a numerical impact score representing the humanitarian value of servicing it:

Impact = (Population × Severity) ÷ 1000

A region with 5,000 affected people at severity level 8 yields an impact score of 40.0. A region with 2,000 people at severity 5 yields 10.0. Higher population and severity both increase the urgency and reward of allocation.

The "resource required" value represents the weight of including a region — analogous to the item weight in a classic knapsack problem.

⚡ Greedy Algorithm

The Greedy approach sorts all regions by their efficiency ratio and allocates resources greedily from highest-efficiency to lowest:

Efficiency = Impact ÷ Resources Required

How it works: Sort all regions by efficiency (descending). Iterate through the sorted list — if the current region fits within the remaining budget, allocate it; otherwise skip. Continue until the budget is exhausted.

Complexity: O(n log n) — dominated by the sort step.

Limitation: The greedy approach is a heuristic. It can fail to find the global optimum when selecting one high-efficiency small region blocks a larger combined gain from two moderate-efficiency regions.

🔬 0/1 Knapsack — Dynamic Programming

The Knapsack DP builds a two-dimensional table dp[i][w] representing the maximum achievable impact using the first i regions with resource budget w.

dp[i][w] = max( dp[i−1][w], dp[i−1][w − res[i]] + impact[i] )

For each region i at each capacity level w, we either exclude it (take the previous row's value) or include it (if it fits, add its impact to the best solution without it). The final answer is dp[n][capacity].

Backtracking through the table reveals exactly which regions were selected in the optimal solution.

Complexity: O(n × W) time and space, where W is the total resource capacity. Provably optimal — no combination is left unchecked.

⚖️ Why Compare Both?

In real emergency operations, coordinators sometimes rely on fast heuristics due to time pressure. ERAS quantifies the cost of approximation — showing exactly how much impact is lost (or gained) by choosing speed over optimality.

In many scenarios the algorithms agree perfectly — Greedy happens to find the global optimum. When they diverge, the difference can represent hundreds or thousands of additional people receiving critical aid.

ERAS's Analytics page tracks win rates over time, giving coordinators insight into how often the faster greedy approach is sufficient for their particular deployment context.

🔌 REST API Reference

The ERAS backend exposes a clean JSON REST API at http://localhost:3000.

GET /api/regions Fetch all active regions
POST /api/regions Add a new region
PUT /api/regions/:id Update a region
DELETE /api/regions/:id Delete a region
DELETE /api/regions Clear all regions
POST /api/allocate Run Greedy + Knapsack allocation (saves to history)
GET /api/history Get all allocation history
GET /api/stats Get aggregate statistics
GET /api/history/export Export history as CSV download
